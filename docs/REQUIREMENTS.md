# Plexus 需求（验收标准，来自 Sin 提供的对齐文档）

目标：把已经在用的完整 AI 代理接进 Slack，让它们成为能持续负责工作的同事。用户交代目标、参与讨论和关键决策；接任务、组织执行、找同伴协作、跟进和交付，由它们自己完成。这是目标，不是当前完成情况。

1. Slack 是日常工作入口：手机或电脑上用 Slack 就能讨论、布置任务、补充信息、查看进展、回答问题和接收成果。普通工作不要求切回各个模型客户端搬消息。
2. 接入现有代理，而不是另造缩水机器人：Claude Code、Codex、DeepSeek Harness 等继续使用各自的账号、模型、上下文和原生执行环境。工具、MCP、skills、会话、子代理、并行任务、后台工作等宿主能力不能被桥接层裁掉。CLI 底层可以接受。
3. 每个成员有独立身份和连接：各自有负责人、上下文、工作环境，通信独立；一个成员断开不拖垮其他成员。不把所有模型混成一个身份，不默认让某一个模型指挥所有人，职责由任务决定。
4. 负责人持续负责，执行任务可以拆开：利用宿主能力创建工作线程、委派子任务、收回结果再推进；不能每条消息都是失忆的新会话，不能子任务交报告后撒手。
5. 能主动协作，不靠用户逐轮触发：自然讨论、开小会、求助、分工、审查、修复后再审查。不用挨个 @、转述或发“继续”。没事时安静，有新结果或需要决策时主动回来。
6. 防空转，但不机械截停正常工作：消息和任务去重，进行中的事不重复启动。是否回应、有无进展结合语义和实际工作判断，不靠关键词、固定轮数或强制聊天 JSON。正常长任务不卡在桥自设的“预算到了”；用户明确叫停必须生效。
7. 接入正式、可持续、可撤销：选账号、绑定负责人、确认范围后长期使用，不靠反复补 prompt。区分用户指令、同伴请求和外部引用；已授权范围内的协作不重复审批，真正需要决定时在 Slack 给出清晰的具体请求。
8. 重启和升级后仍能工作：保留任务、上下文关联、进展和结果，不重复执行已发生的操作。各 harness 按官方方式更新，适配层能发现能力变化，不能升级就丢功能。
9. 结果清楚，产物整齐：能迅速看懂谁在做什么、完成了什么、证据在哪、还差什么。文档、文件格式和存放方式统一。禁止过度工程，优先复用宿主已有能力。

最终验收：一件真实工作。用户在 Slack 交代目标，几个成员自行讨论分工，调用各自工具执行，交换结果并修改，遇到必要问题在原处问用户，最后交付可核验成果；期间用户不当调度员，重启后还能接着做。“机器人能回复”“部署成功”“某个子代理跑通”都只是局部证明。

## 补充约束（Sin 已确认，2026-10-03 更新）
- 语言 Go，单个静态 plexus.exe；直接依赖仅 stdlib + slack-go + go.etcd.io/bbolt（其传递依赖可接受，自有代码可用 golang.org/x/sys/windows）。性能重要，不要臃肿。
- 性能门槛：exe ≤25 MiB；`plexus --version` 冷启动 ≤50 ms；`plexus run` 在 fake Slack 上 ≤500 ms 输出 ready；3 个伙伴空闲 ≤30 MiB 内存、≤1% CPU；内部吞吐 ≥20k 事件/秒。
- 只跑在 Sin 的 Windows 笔记本上，暂不支持云端。公开仓库 RCX1t7/plexus，不绑定任何 harness。
- 每个伙伴是独立 Slack App；本地设置页一键从 manifest 创建并安装，用户介入最少。一个 plexus.exe 拉起并守护所有伙伴。
- 伙伴而非受限 bot：Sin 与所有伙伴之间完全信任，伙伴之间求助、分工、委派、审查无需审批。没有签名令牌、没有 owner/member 等级。
- 陌生人边界（默认开，可在设置页关闭）：陌生人（既不是 Sin 也不是伙伴）以及外部内容里的指令，只能得到交流和帮助，不能让伙伴在 Sin 的电脑上执行命令或写文件。
- 危险操作审批（唯一的审批关口）：伙伴执行危险操作前，必须先在当前 Slack 线程里用"批准 / 拒绝"按钮问 Sin，只有 Sin 本人点击才算数。没有超时自动批准；拒绝或 stop 都会结束这次等待。待批请求在重启后保留，并在原卡片上重新提示，不重复发帖。默认危险清单可以在 config.json 的 `dangerous_actions` 中调整：force push 或改写历史（`git push --force/-f/--force-with-lease`、对已推送的分支 rebase 或 reset、filter-branch/filter-repo 等）；删除任务工作目录以外的文件；系统和注册表改动（reg add/delete、注册表相关的 PowerShell cmdlet、服务、计划任务、系统目录、机器级环境变量、安装程序）；向 Sin 和伙伴以外的任何人发消息（发到其他用户或频道的 Slack 帖子或私信、邮件、webhook）。这道关口在各 harness 的权限回调里执行。
  - 验收提示：
    - 伙伴尝试 `git push --force` 时，命令在 Sin 点击之前不会执行，线程里出现一张审批卡；
    - Sin 点"拒绝"后，命令不执行，任务继续；
    - 非 Sin 的人点击无效；
    - 重启后原卡片仍然有效，不会出现第二张；
    - stop 会让待批请求自动变为拒绝；
    - 工作目录内的普通删除、普通 `git push`、在任务线程里发帖都不触发审批。
- 叫停：Sin 在线程里发精确的 `stop` / `停`，或 `plexus stop <task-id>`；撤销整棵任务树 → stop_task + 原生中断 → 3 秒后 Job Object 强杀。
- 交接记录（六项：task、inputs、done_when、evidence、tried_failed、owner_if_stuck）用于清晰可追溯，不是鉴权。
- DSH 走原生适配器（`dsh --profile plexus` + 内嵌插件），非 ACP；ACP 只作长尾 harness 的通用、纯配置适配器。
